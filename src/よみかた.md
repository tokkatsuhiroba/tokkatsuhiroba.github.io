# src/ の中身と、中身の足しかた

## いちばん大事なこと

**直すのは `src/` の中だけ。`公開用/index.html` は手で触らない。**
`公開用/index.html` は `build.py` が毎回まるごと書き直すので、手で直しても次のビルドで消えます。

```

src/style-simple.css … 見た目ぜんぶ（簡素版・墨1色）
src/storage.js       … 保存はここだけ（将来ネイティブ化するときはここだけ差しかえる）
src/boot.js          … 描く前に表示モードと言語を決める
src/body.html        … 5タブの中身ぜんぶ
src/app.js           … 動きぜんぶ
src/tobira.html      … とびら版（入口の試作）の中身   ★段1
src/style-tobira.css … とびら版の見た目だけ            ★段1
src/ill/*.svg        … イラスト1枚＝1ファイル          ★段1
```

```bash
python3 build.py --check          # 書かずに、中身だけ見る

python3 build.py --tobira         # とびら版の試作
python3 build.py --buhin --mihon  # 部品の検問と見本
```


## 実践を1件足す

1. `src/jissen/_テンプレート.md` をコピーして `2026-09-21_bansho-kata.md` のような名前にする
   **ファイル名の `_` から後ろが、そのままURLの id になります**（`#manabu/j-bansho-kata`）
2. 中を書く。欄の意味は次のとおり

| 欄 | 何を書くか | 出るところ |
|---|---|---|
| `title` | 何をしたかが一目で分かる題名 | 見出し |
| `kind` | `jissen`（既定）か `gidai`。**議題も同じ棚に並びます** | 議題は札に「議題」と小さく出ます |
| `naiyo` | **4つの内容のどれか**（`gakkyu` `gyoji` `jidokai` `club`） | 見出しの上の色つきの札＋「4つの内容」のカードの中 |
| `grade` `scene` `time` | 学年・場面・かかる時間（`time` は議題では要りません） | 見出しの上の1行 |
| `bansho` | 板書の写真のフォルダ名（`src/bansho/◯◯`） | 札に「板書の写真を見る →」／写真は板書のページ |
| `goods` | 使うグッズの id をカンマで（`card, shikai`） | 「セットで使うもの」＋グッズ側の逆リンク |
| `weekly` | 週案にそのまま書ける1行 | 緑の帯（コピーボタン付き） |
| `by` | 提供者。無ければ `本サイト` | 「提供：」 |

3. `---` の下の**最初の段落**が一覧に出る「ひとこと」になります
4. `## 準備するもの` `## 流れ` `## 板書` `## つまずき` は、まとめて
   「くわしく（準備・流れ・板書）」のたたみの中に入ります

`goods` に `src/goods/` に無い id を書くと、**ビルドが止まります**（打ちまちがい対策）。

### 資料（指導案・スライド・板書）を、ページの中で開く　★2026-09-21

PDFは埋めません（端末しだいで開かない／外に通信が飛ぶ）。
**1ページ＝1枚の画像にして、HTMLの中に入れます。**だから外に1本もつながりません。

1. `src/shiryo/◯◯/` を作り、`01.webp` `02.webp` … と**名前の順**に置く
2. .md に1行 `shiryo: 指導案|◯◯`

PDFから画像にするには（横1000px・WebP・品質60。22ページで約1.9MB）：

```bash
python3 -m pip install --user pymupdf
python3 -c "
import pymupdf, os
d = pymupdf.open('もとの.pdf'); os.makedirs('src/shiryo/◯◯', exist_ok=True)
for i, pg in enumerate(d):
    z = 1000 / pg.rect.width
    pg.get_pixmap(matrix=pymupdf.Matrix(z, z), alpha=False).pil_save(
        'src/shiryo/◯◯/%02d.webp' % (i+1), format='WEBP', quality=60, method=6)
"
```

| 上限 | |
|---|---|
| 画像1枚 | 500KB |
| 資料1件（1フォルダ） | 8MB |
| 1ページに入る合計 | 16MB |

超えると**ビルドが止まります**。要らないページは、ファイルごと消せば出ません。

`shiryo:` に `https://…` を書くと、いまも**外のタブが開くリンク**になります（「外部」と出ます）。
ページの中で開きたいものは、フォルダに置いてください。
`naiyo` も同じで、4つ以外を書くと止まります。**空でも止まります**
（どのカードにも集まらない実践を作らないため）。

### 索引 ── 置けない資料を、探せる形にする　★2026-09-21

研究会や個人が作った資料は、**書面の許可が無いと置けません**。
置けないものは、**どこで手に入るかを自分の言葉で書く**。これが索引です。

```
shiryo: 令和8年度 全国大会の紀要|索引:全国特活研のサイトの「過去の大会」から取り寄せられます
```

- **押せる見た目にしません**（押しても何も起きない、を作らないため）
- 説明は**6文字以上**。見出しだけ並べると、ただのリンク集になります。だから止めます
- 説明に `https://` は書けません。URLを出すなら `見出し|https://…` の形にしてください

文科省・国立教育政策研究所のものは、いままでどおり**リンク＋出どころ**で置けます。

## 字を「小」にすると、余白も詰まります　★2026-09-23

**字だけ小さくしても、1画面に入る量はほとんど増えませんでした**（実測で2%）。
空いているのは字と字のあいだではなく、**節と節のあいだ**だったからです。
そこで「小」のときだけ、すきまも詰めます。

| 詰めるもの | ふつう | 小 |
|---|---|---|
| 節と節のあいだ `--aki` | 40〜84px | **24〜48px** |
| 左右の余白 `--pad` | 14〜32px | **12〜24px** |
| 行間 | 1.62 | **1.52** |
| 見出しの下・1行の下・カードとふたの内余白 | — | 2〜3割 詰める |

**実測（1024pxで、ページの高さ）**：ホーム 6950→6536px（6%）／
みんなの実践 3196→2912px（**8.9%**）。そのぶん、1画面に多く入ります。

- **「中」「大」「特大」は1pxも変わりません。**書いてあるのは
  `html[data-moji="chiisai"]` の中だけです（`src/style-hiroba.css` のいちばん下）。
- **詰めるのは すきまだけ。押せる大きさ（46px以上）は削りません。**
  字を小さくした人が押しまちがえるようになっては、意味がないためです。
- 板書の札だけは `--bfuda-pad` を動かします。この値は**写真の窓とつながっている**ので、
  `padding` を直接書くと写真が札からはみ出します（2026-09-23に実際に起きました）。

## 広場で出た悩みを1件足す　★2026-09-21

悩みは .md ではなく、`build.py` の **`NAYAMI` の表**に1行書きます。
ここ1か所に書くと、**2か所に出ます**。

1. 「学ぶ」の**お悩み別の入口** … 学習過程の段階につながる悩みだけ
2. 「4つの内容」の**カードの中** … その内容の悩み、ぜんぶ

```python
NAYAMI = (
    ('gakkyu',  '学級会が話し合いにならない', '2'),   # ②が開く
    ('jidokai', '児童会を任された',           ''),    # 行き先はまだ無い

```

| | 何を書くか |
|---|---|
| 1つめ | 4つの内容のどれか（`gakkyu` `gyoji` `jidokai` `club`） |
| 2つめ | 悩みの言葉。**先生が言うとおりに**。言いかえない |
| 3つめ | 行き先。`'1'`〜`'5'` は学級活動(1)の学習過程の段階。**無ければ空** |

「学ぶ」のお悩み別の入口に出るのは、**上から `NAYAMI_IRIGUCHI` 件**（いまは6件）だけです。
ぜんぶ出すと、入口が入口の役をしなくなります。カードの中には、ぜんぶ出ます。

### LINEから写すときの約束

いま入っている24件は、LINEオープンチャットの 8/9〜9/21 のやりとりから写したものです。
**ここを外すと、書いた人が特定されます。**

1. 発言をそのまま引用しない。**悩みの言葉に言いかえる**
2. 発言者・学校・地域・日付は**一切載せない**（表にも持たせない）
3. 1人の個別事情が分かる書き方にしない。**同じ困りごとの一般形**にする

**行き先が空でも、そのまま出します。**
「LINEで聞く」の破線の札になって、答えがまだ無いことが見えます。
**空の悩みを隠さないのが、この表の要です。**どこが薄いかが、4枚のカードで一目で分かります。

同じ言葉を2回書く／4つ以外の内容を書く／行き先に1〜5以外を書くと、**ビルドが止まります**。

## 4つの内容が、集まる場所です　★2026-09-21

`#yotsu` の4枚のカードが、このサイトの背骨です。
**広場で出た悩みも、届いた実践も、ぜんぶこの4つに集まります。**

## グッズを1点足す・配れるようにする

1点＝`src/goods/` の1ファイル。ファイル名がそのまま id です（`card.md` → `card`）。
並ぶ順は `order:` の数字の小さい順。ファイル名を `_` で始めると出ません。

**いまは6点すべて「準備中」です。** 配れるようにするには、その .md に
`pdf:` と `docx:` のURLを書きます。

```yaml
pdf:  https://……/teian-card.pdf
docx: https://……/teian-card.docx
```

- 両方書く → ボタンが「PDF・Word」に変わる
- 片方だけ → 書いたほうだけ
- どちらも空 → 「準備中」のまま

**「使う実践」の逆リンクは自動です。** 実践側の `goods:` に id を書けば、
グッズの側に「使う実践：◯◯」が出ます。グッズ側には何も書きません。

`icon:` に書くのは `src/body.html` の `<symbol id="g-…">` の id です
（`g-card` `g-post` など）。**グッズ本体の id（`goods-card`）とは別物**なので注意。
同じ id を2つ作るとリンクが別の場所へ飛ぶため、ビルドが止まります。

## フォームのURLを差しかえる

「困りごと・意見を送る」「実践・板書を送る」の行き先は、
**`build.py` の `LINKS`（39〜40行目）1か所だけ**で決まります。

```python
LINKS = {
    'FORM_IKEN'  : 'https://forms.gle/……',
    'FORM_JISSEN': 'https://forms.gle/……',
```

### --moji（読む人が変えられる、字の大きさ）

画面の右下の「あ」を押すと、小・中・大・特大 が出ます。

  そうしないと、その字だけ つまみで動きません
- 枠・余白・ボタンの大きさには掛けていません。
  字を小さくしたときに、押せなくなるためです
- 選んだものは、その端末の中だけ（`localStorage` の `tokkatsu-moji`）。
  外へは1バイトも出ません（原則2）
- **効かせるのは `src/head-hiroba.html` の1行**です。下のほうで入れると、
  ふつうの大きさで一度出てから変わるので、開くたびに字がガクッと動きます

### どうやって動かしているか（ここが肝心）

絵は `<defs>` に1枚入れて `<use>` で使い回しています。
**`<use>` の中には CSS が届きません。中に動きを書いても出ません**（2026-09-22 実測）。

そこで **ホームの絵だけ `<use>` をやめて、絵の本物をそのまま出しています**。

- `build.py` の `ugoki_ireru()` が、人（肌色が入っている `<g>`）と雲を
  `<g class="ug …">` `<g class="ukumo">` で**包む**だけ。絵の線は1本も変えません。
- `build_shin()` が、ホームの絵を `<g id="ill-hiroba">…</g>` として**そのまま**出します。
- `build_tane()` は、本物があるページには同じ絵をもう1枚入れません（id が重なると、ビルドが止まります）。
- 動かし方は `src/style-hiroba.css` の「広場の絵の動き」。`.ug` `.ukumo` と `@keyframes` だけです。

ほかのページ（知る の4つの内容など）は、いままでどおり `<use>` の切り出しです。動きません。
**同じ絵を何枚も本物で出すと、そのぶん重くなります。**本物はホームの1枚だけにしてください。

### 振れ幅を変えたいとき

`src/style-hiroba.css` のこの4つです（絵の中での数。画面ではもっと小さく見えます）。

```css
.ug{--r:3deg}               /* 立つ・座るのゆれ。足もとが軸 */
.ug--hashiru{--rh:2deg;--h:-5px}     /* 走る（倒す角・持ち上げ。横揺れはここ） */
/* 玄関・通り道・入るまでの秒数は build.py の GENKAN / GENKAN_MICHI / GENKAN_BYO */
.ug--te{--rt:3.4deg;--h2:-5px}       /* 手を挙げる */
.ukumo{--kx:80px;--kt:11s}           /* 雲（横に動く幅・1往復の時間） */
@media (max-width:719px){ … }        /* スマホは絵が小さいので、どれも大きめに */
```

速さは `.ug{animation:… var(--t,2s)}` と `.ug--te` `.ug--hashiru` の秒数、
雲は `.ukumo.ug-p0〜p3{--kt:…}` の4つです。

  `data-naiyo` で選び、ページの絵の入れ物にある絵を1枚のSVGに組み直して描きます。
  ★そのページに4人が入っていないと出ません。`src/hiroba.html` の `bansho` の節に、
    画面に出ない `<svg class="ga-tane">` を置いて、4人を呼んでいます。
  ★その中に絵の名前を **字で** 書かないこと。検問が本物の呼び出しと
    まちがえて、ビルドが止まります（1度 踏みました）。
- 頭は1行。前は「サイト名／内容の札／題／場所／日づけ」で5行ありました。

### QRコード

**外のライブラリは1つも読みこみません**（原則2＝何も送信しない）。
`qr_matrix()` が、その場でQRを作ります（バイトモード・誤り訂正レベルM・型1〜10）。

- 型10（216語）を超える長さでは `null` を返し、そのときだけURLを字で出します。
- 1ますのピクセル数は**割り切れる数**にします（`Math.floor`）。中途はんぱだと、
  ますの境目がにじんで読みとれなくなります。
- ★直したら、**かならず読みとって確かめてください。**
  絵として正しく見えても、中身が壊れていることがあります。
  （作るときは、Pythonの `segno` と `opencv` で 66通りの長さを読みとって確かめました）

### 直すときの注意

- 形式の15ビットを置く場所は、**行と列をまちがえないこと**。
  1度まちがえて、見た目は正しいのに読めないQRができました。

## 帯・札・見出しの、色と字　★2026-09-23

### 行き先ごとの色分けは、やめました

もとの決まりは「同じ色は、同じページに着く」で、帯・札・窓の3か所に
ページの色を敷いていました。行き先が7つになり、色が5つ＋白2つ。
7つに7色を当てても同じです。**色の数がふえるほど、1つ1つの意味は薄くなります。**

| どこ | いま |
|---|---|
| 帯 | ぜんぶ同じ。色で言うのは「いまどこ」だけ（墨のベタ塗り） |
| 7つの札 | ぜんぶ同じ地。見分けるのは **しるし**（7つとも別のモノ） |
| 中身をざっとの窓 | 札と同じ |

★しるしを1つ足す・差しかえるときは、**ほかの6つと別のモノ**にしてください。
  色が無いので、形だけが見分ける手がかりです。
★`p--◯◯` のクラスは HTML に残してあります。色をまた敷きたくなったら、
  そこに `--p-iro` を書けば戻せます（`src/style-hiroba.css` に書き置きあり）。

### 「7つのできること」の数

**その場で数えます**（`len(HOME_FUDA)`）。手で書かないこと。
げんに「ぜんぶで、8つ」のまま、中身が7つになっていました。
数が変わる字なので、訳は `KOTOBA` ではなく その場で `data-en` / `data-ar` に入れます
（札の件数＝`home_kazu` と同じ考えです）。

### 送る欄は「小」から始める

`.okuru-f{--moji:.8}`。つまみは そのまま効きますが、**1段ぶん小さい所から**始まります。
「小」より下には行きません。入力欄の字（16px）と押せる大きさ（44px以上）は
掛け算していないので、変わりません。

### 「中身を、ざっと」の量

`--mi-z`（`.atama-in`）が窓の中の縮尺です。**小さいほど たくさん映ります。**
1＝実寸。2026-09-23 の依頼で `.72` にし、窓も少し高くしました。
読めなくなったら、この数を上げれば戻せます。
