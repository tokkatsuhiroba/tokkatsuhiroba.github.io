# src/ の中身と、中身の足しかた

## いちばん大事なこと

**直すのは `src/` の中だけ。`公開用/index.html` は手で触らない。**
`公開用/index.html` は `build.py` が毎回まるごと書き直すので、手で直しても次のビルドで消えます。

src/boot.js          … 描く前に表示モードと言語を決める
src/body.html        … 5タブの中身ぜんぶ

1. `src/jissen/_テンプレート.md` をコピーして `2026-09-21_bansho-kata.md` のような名前にする
   **ファイル名の `_` から後ろが、そのままURLの id になります**（`#manabu/j-bansho-kata`）

| 欄 | 何を書くか | 出るところ |
|---|---|---|

| `kind` | `jissen`（既定）か `gidai`。**議題も同じ棚に並びます** | 議題は札に「議題」と小さく出ます |
| `naiyo` | **4つの内容のどれか**（`gakkyu` `gyoji` `jidokai` `club`） | 見出しの上の色つきの札＋「4つの内容」のカードの中 |
| `grade` `scene` `time` | 学年・場面・かかる時間（`time` は議題では要りません） | 見出しの上の1行 |
| `bansho` | 板書の写真のフォルダ名（`src/bansho/◯◯`） | 札に「板書の写真を見る →」／写真は板書のページ |
| `goods` | 使うグッズの id をカンマで（`card, shikai`） | 「セットで使うもの」＋グッズ側の逆リンク |
| `weekly` | 週案にそのまま書ける1行 | 緑の帯（コピーボタン付き） |
| `by` | 提供者。無ければ `本サイト` | 「提供：」 |

3. `---` の下の**最初の段落**が一覧に出る「ひとこと」になります
4. `## 準備するもの` `## 流れ` `## 板書` `## つまずき` は、まとめて
   「くわしく（準備・流れ・板書）」のたたみの中に入ります

`goods` に `src/goods/` に無い id を書くと、**ビルドが止まります**（打ちまちがい対策）。

### 資料（指導案・スライド・板書）を、ページの中で開く　★2026-09-21

PDFは埋めません（端末しだいで開かない／外に通信が飛ぶ）。
**1ページ＝1枚の画像にして、HTMLの中に入れます。**だから外に1本もつながりません。

1. `src/shiryo/◯◯/` を作り、`01.webp` `02.webp` … と**名前の順**に置く
2. .md に1行 `shiryo: 指導案|◯◯`

PDFから画像にするには（横1000px・WebP・品質60。22ページで約1.9MB）：

```bash
python3 -m pip install --user pymupdf
python3 -c "
import pymupdf, os
d = pymupdf.open('もとの.pdf'); os.makedirs('src/shiryo/◯◯', exist_ok=True)
for i, pg in enumerate(d):
    z = 1000 / pg.rect.width
    pg.get_pixmap(matrix=pymupdf.Matrix(z, z), alpha=False).pil_save(
        'src/shiryo/◯◯/%02d.webp' % (i+1), format='WEBP', quality=60, method=6)
"
```

| 上限 | |
|---|---|
| 画像1枚 | 500KB |
| 資料1件（1フォルダ） | 8MB |
| 1ページに入る合計 | 16MB |

超えると**ビルドが止まります**。要らないページは、ファイルごと消せば出ません。

`shiryo:` に `https://…` を書くと、いまも**外のタブが開くリンク**になります（「外部」と出ます）。
ページの中で開きたいものは、フォルダに置いてください。
`naiyo` も同じで、4つ以外を書くと止まります。**空でも止まります**
（どのカードにも集まらない実践を作らないため）。

### 索引 ── 置けない資料を、探せる形にする　★2026-09-21

研究会や個人が作った資料は、**書面の許可が無いと置けません**。
置けないものは、**どこで手に入るかを自分の言葉で書く**。これが索引です。

```
shiryo: 令和8年度 全国大会の紀要|索引:全国特活研のサイトの「過去の大会」から取り寄せられます
```

- **押せる見た目にしません**（押しても何も起きない、を作らないため）
- 説明は**6文字以上**。見出しだけ並べると、ただのリンク集になります。だから止めます
- 説明に `https://` は書けません。URLを出すなら `見出し|https://…` の形にしてください

文科省・国立教育政策研究所のものは、いままでどおり**リンク＋出どころ**で置けます。

## 字を「小」にすると、余白も詰まります　★2026-09-23

**字だけ小さくしても、1画面に入る量はほとんど増えませんでした**（実測で2%）。
空いているのは字と字のあいだではなく、**節と節のあいだ**だったからです。
そこで「小」のときだけ、すきまも詰めます。

| 詰めるもの | ふつう | 小 |
|---|---|---|
| 節と節のあいだ `--aki` | 40〜84px | **24〜48px** |
| 左右の余白 `--pad` | 14〜32px | **12〜24px** |
| 行間 | 1.62 | **1.52** |
| 見出しの下・1行の下・カードとふたの内余白 | — | 2〜3割 詰める |

**実測（1024pxで、ページの高さ）**：ホーム 6950→6536px（6%）／
みんなの実践 3196→2912px（**8.9%**）。そのぶん、1画面に多く入ります。

- **「中」「大」「特大」は1pxも変わりません。**書いてあるのは
  `html[data-moji="chiisai"]` の中だけです（`src/style-hiroba.css` のいちばん下）。
- **詰めるのは すきまだけ。押せる大きさ（46px以上）は削りません。**
  字を小さくした人が押しまちがえるようになっては、意味がないためです。
- 板書の札だけは `--bfuda-pad` を動かします。この値は**写真の窓とつながっている**ので、
  `padding` を直接書くと写真が札からはみ出します（2026-09-23に実際に起きました）。

## お名前と所属を、この端末が覚えます　★2026-09-23

「再修正をするときに、名前と所属をもう一度入力しないといけない。
一度入力してあるものは覚えておいて」という依頼です。

**なぜ空だったか。** ［なおす］は、公開ページの札に書いてある `data-*` から
もとの字を持ってきます（題・学年・内容・推し・地域・資料・本文）。
けれど **お名前・所属・「名前を出してよい」の印は、札に載っていません**
（所属は「サイトには出しません」と約束しているためです）。
持ってくる先が無いので、なおすたびに空でした。

**覚えかた。** しまう所は2つです。どちらも **その端末の `localStorage` だけ**。
送るのは［送る］を押したときだけで、原則②（開いても外に1バイトも出ない）は
そのままです。

| 鍵 | 中身 | いつ使うか |
|---|---|---|
| `tokkatsu-aikotoba` の1件 | その1件の `na` / `sh` / `ko` | ［なおす］で、**その1件**の名前に戻すとき |
| `tokkatsu-nanori` | 最後に送った `na` / `sh` / `ko` | 2件めを送るとき・控えの無い古い1件をなおすとき |

順番は **控えが先、`tokkatsu-nanori` はその次**です。所属を書きかえて送った人が、
古いほうの所属で出てしまわないようにするためです。
なおして送ったときは、控えのほう（題も一緒に）も書きかえます
（`aikotoba_kakikae`）。そろえないと、2回めの［なおす］で古い名前が出ます。

**入れない場合が2つあります。**

- **管理画面から来たとき**（`naoshi.kanri`）… 送り主の名前を、管理人の名前で
  上書きしてしまいます。管理画面には もともと お名前・所属の欄があります。
- **お悩みBOX** … 名前は任意のままで、こちらでは入れません。
  「うまくいっていないと打ち明ける」ところに名前が最初から入っていると、
  出すつもりのなかった名前が、そのまま出ます。

**共用の端末のために。** 入れたときは、お名前の欄の下に
「まえに この端末で書いたお名前と所属を入れてあります」と1行出して、
［消す］を添えます（`.okuru-nanori`）。押すと、欄も 覚えているものも消えます。
なおしている最中は、この1行は出しません（その1件のものなので、
前の話に見えてしまいます）。

★スマホの `.bansho-b` は「幅いっぱいの札」です。ここの［消す］だけは
`display:inline-flex; width:auto` で横に添えます（押せる高さ44pxはそのまま）。

## 実践1件ごとの「LINEの絵」は、出せません　★2026-09-24

理由は2つあり、**どちらか片方を直しても解決しません**。

1. リンクが `…/bansho.html#b-スラッグ`。**「#」より後ろは相手に届きません。**
   ブラウザが自分の中だけで使う目じるしだからです。LINEが見るのは
   `bansho.html` 1枚ぶんの情報だけ。何件あっても同じ絵になります。
2. **実践の写真は、外から取れるアドレスを持っていません。**
   `shiryo_yomu()` がHTMLの中に `data:image/webp;base64,…` として溶かしこみ、
   GitHubへ上げるのはHTMLと `ogp*.png` だけです。`og:image` に data URI は
   書けません（LINEもFacebookもXも読みません）。

「実践1件＝1ページ」にすれば技術的には できますが、ページの外枠（CSS・JS・
キャラのSVG。1枚あたり約520KB）が実践の数だけ複製され、**サイトが約5.5MB
増えます**。さらにOGP画像を1件ごとに手で作って置く作業が永久に発生します
（`tsukuru.py` は macOS の `qlmanage` を使うので GitHub Actions では走りません）。
**フォームから手を触れずに公開される、という一番の美点が、そこで途切れます。**

★技術ではない理由もあります。`KAKUSU_E` で「実践と困りごとの絵は検索に
出さない（子どもの顔が画像検索に並ばないように）」と決めています。黒板写真を
LINEのプレビューに出すのは、この方針と正面からぶつかります。

ページ単位で絵を選ぶ仕組み自体は `OGP_E` / `head_de` にあり、`okuru.html` と
`komari.html` で使っています。

## 大きく見るときの、ボタンの位置　★2026-09-24

スマホで写真を大きくしたとき、［大きく］［閉じる］が下すぎて押しにくい、という話。

- **`env(safe-area-inset-bottom)` は書いてあったのに、効いていませんでした。**
  `.zen-te` で `padding-bottom:max(12px,env(...))` と指定したあと、後ろの
  `@media (max-width:719px)` の `padding:8px 10px` が **一括指定で丸ごと
  上書き**していたためです。実測でボタンの足が画面の下から8pxでした。
- 下だけを厚くします … `max(36px, calc(env(safe-area-inset-bottom,0px) + 16px))`。
  ふつうの端末で36px、ホームバーのある端末はそのぶん＋16px。
- **よこ持ちの小さい画面**（`max-width:719px and max-height:480px`）だけ18px。
  写真がつぶれるためです。
- パソコン（1200×800）は12pxのまま **変えていません**。ボタンが写真の
  まんなかに浮いて見えないようにするためです。
- ボタンの大きさ（44×69px）も字（12.5px）も変えていません。
